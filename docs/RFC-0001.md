# RFC-0001：自由匿名 P2P IRC 架构

- 状态：Draft / implementation-backed
- 版本：0.2
- 所属组织：KairoteStudio
- 最后更新：2026-10-01

## 1. 定义目标

Kairc 的目标不是建立另一个中心 IRC 网络，而是提供一个可由个人运行的通信节点：本地应用继续使用简单、成熟的 IRC 接口，跨设备通信则由匿名友好的 P2P event graph 承担。

这里的“自由”有三个可测试含义：客户端可替换、节点可自托管、网络可分叉。这里的“匿名”也有明确边界：协议不要求现实身份或稳定账户；应用不主动公开本机资料；网络路径可以通过 Tor 隐藏来源。它不承诺对全局被动观察者、被攻陷终端或恶意联系人实现绝对匿名。

## 2. 参考模型

DarkFi 的 DarkIRC 证明了一个实用分层：IRC 服务器只监听本机，P2P 网络和 Event Graph 在节点间同步消息，网络 transport 与频道加密分别处理。DarkFi 文档还明确说明公开频道为明文、昵称不是现实身份、Tor 不能消除所有元数据。

Kairc 沿用这些结构原则，但使用独立的 C++23 实现和更小的首版协议。当前实现不是 DarkFi 兼容节点。

## 3. 信任边界

```text
┌──────────────┐ trusted local boundary ┌──────────────────────┐
│  IRC client  ├────────────────────────► local IRC gateway    │
└──────────────┘                         │                      │
                                         │ channel codec        │
                                         │ event validation     │
                                         │ rotating SQLite DAG  │
                                         └──────────┬───────────┘
                                                    │ encrypted frames
                                         ┌──────────▼───────────┐
                                         │ Tor/SOCKS5 or direct │
                                         │ P2P peers            │
                                         └──────────────────────┘
```

IRC 客户端和本机 `kaircd` 位于同一个信任域。P2P peers、收到的事件、数据库中同步来的字节全部不可信。

## 4. 身份

Kairc 0.2 没有账户系统。

- IRC nickname 是消息载荷中的可变 pseudonym，不证明控制权。
- 本地实现为每个事件生成新的 Ed25519 密钥，公钥只用于验证该事件内部一致性；恶意 peer 仍可主动复用自己的 key，因此它不是可信身份。
- 节点重启或连续发言不会因为签名公钥而自动关联。
- 网络连接使用临时 X25519 会话密钥，不公布持久 node ID。
- `USER` 与 realname 只用于完成 IRC 客户端握手，随后丢弃。

代价是 Kairc 不能提供“这个昵称仍是昨天那个人”的协议保证。需要稳定身份的社区可以在更高层交换签名证明，但不应把它强制成加入网络的条件。

## 5. Event Graph

时间被划分为一小时 epoch。每个事件包含：

- 协议版本与事件类型；
- network hash 与毫秒时间戳；
- 单事件 Ed25519 公钥；
- PoW nonce；
- 1–4 个同 epoch parent；
- channel tag；
- payload nonce 与 payload；
- Ed25519 signature。

每个 epoch 有由 network hash 和 epoch number 导出的虚拟 root。没有当前 tip 的事件引用这个 root。节点只有在所有非 root parent 已经提交、且 parent 属于同一 epoch 时，才能提交 event body。

事件 ID 是完整签名事件的 BLAKE2b-256 内容地址。节点用 ID 去重，inventory 只发送有界数量的近期 ID，缺失事件及其 parent 通过 `GET` 递归获取。

默认保留 24 个小时 DAG。删除完整旧 epoch 不破坏新 epoch 的 parent closure。

## 6. 匿名抗滥用

没有账户意味着无法按账户限流。当前版本要求事件 hash 满足配置的前导零位数，相当于一个简化 Hashcash。它满足：

- 验证成本远低于生成成本；
- 不需要中心身份；
- 难度属于网络参数，异构难度的节点不会互通事件。

它不提供公平性，也不能阻止 GPU/ASIC 或大型 botnet。未来协议可以引入 RLN 或其他匿名凭证证明，但必须先给出独立 RFC、公共参数生命周期、double-signal 处理和恢复流程。

## 7. 频道隐私

公开频道 tag 从 network 与 canonical channel name 派生，载荷为明文。私密频道 tag 从 network 与共享密钥派生，载荷使用 XChaCha20-Poly1305 加密。AEAD associated data 绑定 version、kind、network、timestamp、一次性 author key、parents 和 channel tag；攻击者不能把截获的密文包装进自己签名的新事件来重复投递。

共享密钥频道隐藏 nickname 和 message body，但不隐藏：

- 稳定的频道 tag；
- event 时间、大小、parent 和传播路径；
- 参与节点的在线时序；
- 拥有密钥的恶意成员观察到的信息。

共享密钥方案没有每成员撤销和前向保密。未来多人密钥协议不能在未完成密码学评审前标记为“安全群聊”。

## 8. P2P transport

节点握手交换 network hash 和临时 X25519 公钥，通过 libsodium `crypto_kx` 派生方向独立的会话密钥。每个 frame 使用递增 nonce 的 XChaCha20-Poly1305 加密并设置 1 MiB 上限。

这能防止被动链路观察者读取 frame，并能检测 frame 篡改。握手没有持久身份认证，所以 direct TCP 上的主动中间人仍可拆分连接、观察公开内容、阻断或重放有效事件。签名事件不能被中间人无声修改；私密频道 payload 还有独立的端到端密钥。

匿名网络默认路径应为 Tor onion service。`tcp://` 是开发和受控网络 transport，不是匿名模式。

## 9. 自由与治理

自由不是单一运营者的“无规则公共房间”。Kairc 把治理下放：

- 节点可以选择 peers、retention、PoW 与本地可读频道；
- 私密频道的密钥由成员自己控制；
- 任意网络可以使用新的 `network_id` 独立分叉；
- 过滤和客户端呈现属于本地策略，不由中心服务强制；
- 核心网络不设置全局昵称、中心封禁表或不可退出的服务条款。

0.2 尚未实现可传播的 moderation event。加入前必须先定义其权限来源、撤销和滥用边界。

## 10. 安全不变量

1. 未通过签名、network、PoW、大小与时间检查的事件不得进入 store。
2. 非 root parent 不完整时，event body 只能进入有界 pending queue。
3. 一个 epoch 的事件不得引用其他 epoch 的 parent。
4. P2P frame、inventory、event、IRC line、pending queue、本地频道表和连接槽位都有硬上限。
5. 私密频道认证失败时不得尝试把 ciphertext 当成公开消息解析。
6. 私密 ciphertext 必须认证其签名事件上下文，不能在另一个事件外壳中复用。
7. IRC listener 不得绑定非 loopback 地址。
8. SOCKS5 必须把域名交给 proxy，不能预先执行本地 DNS 查询。
9. 应用默认日志不得包含 peer address、nickname 或 message body。

## 11. 里程碑

### 0.2：当前原型

- C++ event graph、签名、PoW、SQLite parent closure；
- 本地 IRC gateway；
- 加密 P2P frame、静态 peer、Tor SOCKS5；
- 公开与共享密钥频道；
- ASan/UBSan CI、TSan 验证和双节点加密传播测试。

### 0.3：可测试匿名网络

- peer discovery、连接槽位与可审计的 host lifecycle；
- header-first / range sync 与更严格的字节 metering；
- 可替换匿名抗滥用 proof 接口；
- 覆盖 parser 与 wire format 的持续 fuzzing 和故障注入测试；
- onion service 运维手册。

### 1.0：公开网络候选

- 独立密码学与协议安全审计；
- 至少三个独立 seed/operator；
- 参数升级、数据库迁移和灾难恢复流程；
- 可复现构建和稳定 wire version；
- 明确的漏洞响应与版本支持政策。
